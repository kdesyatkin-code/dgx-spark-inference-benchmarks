Хеш-таблица находит значение за два шага: хеширование и прямой доступ по индексу.

1. Ключ пропускается через хеш-функцию — получается число (хеш).
2. Хеш берётся по модулю от размера массива bucket'ов — это индекс ячейки.
3. В ячейке сравнивается ключ: совпал — возвращаем значение. Среднее время O(1), потому что второй шаг сразу указывает куда смотреть.

Коллизии: разным ключам может соответствовать один хеш (или один индекс). Таблица не теряет данные — варианты разрешения:

- Цепочки (chaining): в bucket'е хранится список пар (ключ, значение), при коллизии добавляем в конец.
- Открытая адресация: если ячейка занята, пробуем следующую по правилу (linear probing, double hashing).

Пример, массив из 5 bucket'ов, хеш = длина ключа mod 5:

  "apple"  -> 5 mod 5 = 0  -> bucket[0]: (apple, 1)
  "mango"  -> 5 mod 5 = 0  -> коллизия -> цепочка bucket[0]: (apple,1) -> (mango,2)
  "fig"    -> 3 mod 5 = 3  -> bucket[3]: (fig, 3)

Поиск "mango": хеш = 0, идём в bucket[0], сравниваем ключ "apple" — не тот, следующий в цепочке "mango" — совпал, вернули 2.

Ключевой момент: при низкой загрузке (количество элементов много меньше bucket'ов) цепочки остаются короткими, поэтому поиск остаётся близким к O(1); при высокой загрузке таблица расширяется (rehashing) и все ключи перекладываются в новый массив.
